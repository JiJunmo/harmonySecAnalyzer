## 工作流

`项目事实 -> 组件渐进式语义探索 -> 确定性组件连接 -> 六维验证 -> Root Cause Finding`

一个 Ability/ExtensionAbility 对应一个逻辑探索和一个持久任务记录，可按单轮容量派发多个短任务。Agent 每轮通过受控命令领取安全语义断点，优先使用 Atlas 定位关系；Atlas 缺失动态分派边时，只围绕当前调用点和绑定、赋值、覆写或注册点核实源码，在一步内连续分析普通 helper、继承实现和连续调用，不做漏洞判断。发现敏感操作只记录，不是停止条件。运行时优先走完当前路径，路径闭合且本轮函数预算尚有余量时再继续下一条；长路径达到保护值时保存当前证据和后续断点，下一轮换新上下文续跑。只在安全状态变化、关键分支、组件边界、未解析目标或步骤容量用完时保留后续断点。运行时按“函数符号 + 攻击者控制状态 + 身份关系 + 已经过的安全检查”去重。所有断点完成、明确停止或形成覆盖缺口后，脚本生成唯一组件语义结果，Agent 不手写该结果。

通过组件通信机制进入另一个 Manifest 组件时停止，分别记录调用触发控制、参数映射、调用主体和权限变化；继承、`super`、helper 与审计范围内可读的依赖实现不构成组件跳转。系统 API、没有项目源码的边界、相同安全状态的循环和已证明失去全部攻击者影响的分支可以停止；Atlas 与受限源码核实都无法解析的目标必须形成覆盖缺口。普通分支仅在能力、操作、受控参数和安全检查语义一致时合并为一个 Operation Group；防护代码只作为客观事实记录。

容量不足不是路径终点：步骤容量用完时将已知待分析目标保存为 `successors`，`stop_reason=null`；本轮需要换上下文时设置独立的 `pause_requested=true`，再通过 next/finish 接续。Agent 不填写步骤 status 或后续目标 decision。失败分支只在 `gaps[]` 中声明一次目标、原因和证据，其他待分析分支照常保存；查询里的 `unresolved_targets` 是工具观察，不是覆盖结论。未知目标不创建虚构 successor。组件总量保护由脚本独立处理，Agent 不输出 `resource_limit`。

每组按调用顺序使用必要的 `entrypoint/reachability/control/transform/security_check/operation/dead_end` 类型保存最短证据链；“最短”只能删除无关普通节点，不能删除会改变后续安全结论的分支、转换、身份变化和安全检查。禁止无真实调用或数据关系的入口与 API 笛卡尔组合，但必须从真实组件输入沿执行关系发现操作。facts 只能是源码事实，不允许使用 `effect` 类型承载推断，解析缺口只写步骤 gaps。类型按实际证据选用，不要求每种都存在。节点之间的相邻关系由运行时根据顺序确定性生成。

## 可利用性

全部语义结果落盘后，脚本从已确认的外部入口连接组件参数映射以及身份、权限变化，只把外部可达的本地操作和成功连接的跨组件操作交给独立验证任务。未导出组件可以作为下游节点，但不能作为外部根入口。验证任务对每个操作组检查反证并记录业务意图、安全边界、安全检查 结论和六维判断；跨组件组还必须判断下游校验约束的是原始主体还是仅约束了被借权的中间组件。它可以沿当前操作组已有关系读取定性所需的全部调用链源码并使用 Atlas 核实，但不能发现新的独立操作、新增操作组、另建路径或改写已落盘语义事实。

能力定点模式会为全部 Manifest 组件创建所选能力的语义任务。能力表中的 `entry_types` 只用于提示 Agent 优先核对常见入口，不作为组件排除条件。

只有 `confirmed_vulnerability` 要求六项全部为 true。第二维“攻击者控制”同时覆盖安全关键参数受控和操作触发受控，不要求虚构参数传递。有效安全检查为 `protected_exposure`；外部可达、操作控制或操作可达被明确反证为 `no_exploitable_path`；正常公开业务且未越界为 `benign_business_flow`；基础路径成立但后续缺关键证据为 `residual_risk`；基础路径本身无法建立为 `insufficient_evidence`。`true/false` 均必须有非假设证据，没有找到证据只能使用 `unknown`。

根因身份由操作位置、关键受控参数和安全边界组成。普通分支、入口别名和能力 ID 不参与根因身份。路径只为 confirmed vulnerability 和 residual risk 生成，作为报告证据，不作为调度对象。

## Atlas 使用

从运行时领取的当前断点出发，先使用 `search/symbol/explore/calls/path/trace/impact` 渐进追踪（当前工具下对应 `{{atlas_prefix}}search` 等名称）。每个 Atlas 已解析目标都必须明确记录为“当前步骤已分析”或“作为断点继续/停止”；需要继续的断点由运行时排队，Agent 不在一次上下文中无限展开。Atlas 缺失动态调用边时，可直接阅读当前调用点及对应的绑定、赋值、注册、覆写或分派实现；只有同时具备调用点和目标绑定点证据，才能补入关系。入口发现没有项目内调用点时，使用候选触发依据和 callback 实现位置。仅凭名称、类型或注释推测，以及无锚点逐文件扫描，都不允许。沿已证明的继承实现、`super`、公共 handler、依赖实现和异步回调继续追踪；只有真实组件通信才记录 `component_calls` 并停止。组件调用必须分别记录调用触发是否受控、参数控制性、下游观察身份、原始身份绑定状态和实际使用的权限；没有参数传递不等于没有受控调用。两种方式都不能解析的表达式写入步骤 `gaps`，由脚本汇总到 `coverage.unresolved_targets`。NAPI/native 不在当前范围。
